## 2. Design concept: "engineering sheet"

Siddhrans sells engineering rigour, so the site reads like a well-made engineering drawing, not a SaaS template.

- **Surfaces:** warm paper `#F5F3EC` and graphite `#14171B`, with hairline rules, dot-grid paper behind heroes, sheet-numbered sections (`§ 03`) and title-block summaries on inner pages.
- **Brand accents, controlled:** logo green (sampled ≈ `#009040`) appears as rules and markers; a darker step (`#00763A`) is used for text and buttons so they pass AA contrast; logo yellow (≈ `#F8E000`) is only a highlighter behind key words and a single "engineering solutions" tag. No gradients, glass or stock photography.
- **Type:** Archivo (headlines), Hanken Grotesk (body), IBM Plex Mono (sheet markers, status tags, signal chains).
- **Signature visual:** an isometric **capability stack** that mirrors the company profile's "seven disciplines, one system", with security as a green bar running through every layer and managed services as the dashed enclosure. Embedded and Industrial IoT is the dark base layer, which reflects its new positioning.
- **Embedded & IoT section:** a dark band with a **Sense → Control → Connect → Analyse → Act** signal chain, drawn in line icons.
- **Motion:** staggered hero reveal, plate-by-plate drawing of the stack, scroll reveals, hover rule-and-highlight on the capability index. All of it switches off under `prefers-reduced-motion`.
- **Honest labelling as a design feature:** every capability and use case carries a status tag (*Systems built*, *Engineering capability*, *Engineering solutions*, *Designed system*, *Proposed solution*, *Reference prototype*, *Capability example*). This makes the ownership problem visible and designed, rather than hidden in footnotes.
- **Imagery:** all visuals are original SVG schematics. No photographs are used, so there is nothing to mislabel as a project photo.

## 5. 21st MCP re-assessment (not installed)

Verified from the vendor's own pages today (GitHub repo `21st-dev/magic-mcp`, `21st.dev/pricing`, `/privacy`, `/terms`):

| Question | Finding |
|---|---|
| Official source | `github.com/21st-dev/magic-mcp`; setup via `21st.dev/mcp`. |
| Licence of the tool | **ISC** (permissive). |
| Access | API key required; connects to a hosted MCP at `https://21st.dev/api/mcp`; the legacy `@21st-dev/magic` npm proxy forwards every message to 21st's servers. |
| Pricing | Free plan ($0): 2 free component "copies" per day. Builder $6/mo yearly or $8 quarterly; Builder + AI $15 / $30 / $60 per month by credits. Pricing page does not confirm whether Free includes MCP retrieval. |
| Data sharing | Prompts and tool traffic go to 21st's servers. Privacy policy covers prompts, code and "other materials you submit"; logs kept up to 12 months; subprocessors include Anthropic, OpenAI, Sentry and Langfuse. It states 21st does not train its *own* models on customer prompts. It never mentions MCP by name. |
| **Component licensing (the real issue)** | Terms: marketplace components belong to "their respective authors and 21st Labs"; use is "solely through the official 21st.dev platform"; **no express commercial-use grant**; open-source components keep their own licences and need attribution. The terms say nothing about ownership of AI-generated output. |

**Recommendation: still do not adopt for this project.** The visual direction is deliberately bespoke, and community components would pull the site back toward generic patterns. They would also add an unclear licence on a corporate website, plus a third party seeing project prompts. If you still want it as a reference tool only, I would use it on a throwaway scratch project, never for code shipped on siddhrans.com, and get written confirmation from `support@21st.dev` about commercial use first. Graphify, Compound Engineering and Harvey remain excluded.
